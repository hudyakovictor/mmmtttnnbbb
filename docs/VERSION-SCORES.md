# Оценка версий (0–1000)

Проверены все версии в репозитории: 4 архива + рабочее дерево (финальный FALL LINE).
Все версии, где есть код, собраны/прогнаны: `v1`, `v2` и `main` проходят `tsc` и `vite build` без ошибок.
`v3`/`v4` — это пустые стартеры-заготовки (сборка не имеет смысла).

## Методика

Оценка от 0 до 1000 по 8 критериям с весами, где вес смещён в сторону **соответствия заданию**
(цель — Three.js-игра с физикой и процедурным миром, т.е. downhill-игра FALL LINE):

| Критерий | Вес |
| --- | --- |
| Соответствие заданию (жанр/стек) | 25% |
| Полнота и работоспособность | 20% |
| Геймплей / симуляция | 20% |
| Графика и 3D | 10% |
| UI / HUD / меню | 10% |
| Аудио | 5% |
| Архитектура / качество кода | 5% |
| QA (тесты, диагностика) | 5% |

## Разбор

### v4 — пустой Vite-стартер — 50/1000
`src/App.tsx` — заглушка «Ready to build / Start prompting». Никакой игры, никакого Three.js,
никакой физики. Плюс только в том, что взят правильный инструмент (Vite+TS) и он компилируется.
Это скелет, а не решение.

### v3 — пустой Next.js/PostgreSQL-стартер — 55/1000
Шаблон «Arena Next.js PostgreSQL Starter»: `/api/health`, Drizzle-схема, `select 1`.
Инженерно чуть больше, чем v4 (health-check, lint, typecheck), но стек для WebGL-игры не нужен
(Next + Postgres — лишняя инфраструктура), а игры — ноль. По заданию это дальше, чем v4.

### v1 — 360° детектив — 540/1000
Рабочая, законченная игра: intro → исследование панорам → сбор улик → дедукция → победа.
Three.js-сфера-панорама с drag/gyro, «машина времени» before/now/after, 4 локации, полный UI
(HUD, модалки, тосты, виньетка/сканлайны). Типизированная модель данных, чистая React-архитектура,
сборка в один файл (2.4 МБ). **Но**: это не тот жанр — вместо downhill-симуляции сделана
детективная панорама. Three.js задействован минимально (текстурированная сфера, без физики и
процедурного мира), нет аудио, нет тестов/диагностики, нет compliance со skills-фреймворком.

### v2 — 360° детектив v2 — 620/1000
Эволюция v1: добавлены процедурный Web Audio (клики, «затвор», «вууш», resolve), система
подсчёта с вопросами-дедукцией (правильно/неправильно), поток «нитей» расследования, туториал,
хоткеи (1/2/3 — эпохи, J — дело, Esc), фото улик/портреты, CSS-фильтры эпох + дождь, фазы
boot/intro/briefing/game/verdict. Объективно самая полная и отполированная из «неправильных»
версий, сборка в один файл (3.6 МБ). **Но** остаётся тем же неверным жанром: ноль физики,
ноль симуляции, ноль compliance со skills, нет тестов.

### main — FALL LINE — 900/1000
Целевой результат. Это настоящая Three.js downhill-игра (~2700 строк TS, строгий `tsc`, чистая сборка):
- **Физика**: кастомный raycast + пружинная подвеска, Pacejka-lite (продольное/поперечное скольжение),
  PID-наклон с пробами берм, рейл-ассист/Pro, bunny hop, фиксированный шаг симуляции.
- **Мир**: сплайновая трасса ~1.3 км, общий heightfield (меш + лучи), процедурные инстансы сосен/камней,
  terrain-blend шейдер, ACES/fog/небо, quality-тиры.
- **Системы**: камера (chase + lookahead + тряска), процедурный звук (ветер/качение/занос/удары),
  VFX (пыль, взрыв, хитстоп), полный HUD/меню/тач.
- **QA**: тест-хуки (`__THREE_GAME_TEST_HOOKS__`), диагностика (`__THREE_GAME_DIAGNOSTICS__`),
  Playwright-тесты + inspector-скрипт, seeded RNG.

Почему не 1000: генераторы и API-ключи (TRIPO/GEMINI/ELEVENLABS) отсутствуют — заявлен легальный
процедурный fallback, но premium-ветка не закрыта; риск установки headless Chrome в CI; живой
рендер кадра не верифицирован (нужен GPU/headless-браузер) — оценка по коду, сборке и тестам.

## Вывод

Эволюция видна: v3/v4 — пустые стартеры (~0 игрового контента), v1/v2 — цельные, но
**не того жанра** игры (детектив вместо downhill), main — целевая симуляция. Разрыв между
«сделано что-то рабочее» (v1/v2) и «сделано то, что требовалось» (main) — главный фактор оценки.
